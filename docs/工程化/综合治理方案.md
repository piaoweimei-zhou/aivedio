## 三、治理原则（不可违背）

1. **先备份，后动手**：治理前先将当前全部改动 commit，打基线标签 `v0.9-baseline`。
2. **先提交，再移动，后删除**：P0 **Step 0 必须先 stage/commit 全部 untracked 文件**（含整个 `backend/tools/`、QC 新功能 `asset_organizer.py`/`qc_stage.py`/`QcReportCard.tsx` 等），确保 `git clean -fdx` 或误恢复不会抹掉真实工作；移动优先适用于真实文件，物理删除仅限纯垃圾（见 11.1，且 `dist/` 有重建条件）。
3. **不破坏运行**：路径收敛/目录迁移后必须回归「启动 + 一键成片 + 资产读写 + `/output`、`/assets/uploads` HTTP 访问」。
4. **分阶段小步交付**：每个阶段结束必须过验收线，再进下一阶段。
5. **与 bupvideo 工程化体系对齐**：能直接移植的（入口/规范/门禁/看板/发布/巡检）一律移植，不重复造轮子。

## 五、七化落地方案（每化：动作 → 验收）

### 5.1 工程化（可操作、有入口）
- 动作：建 `director.py` 统一入口（start/test/gates/dashboard/release/health/status）；**建 `services/paths.py` 收敛全部运行时路径**；依赖用 requirements.lock 锁定（已有）；`services/` 大文件拆分至 40KB 以下（P2）。
- 验收：一切操作走单一入口；backend 根级无临时文件；无 40KB+ 单文件；grep 无散落的目录根定义。

### 5.2 标准化（有规矩、可对齐）
- 动作：引入 black + isort + flake8（backend）与 ESLint + Prettier（frontend，需新增 devDependencies）；定义目录/命名/错误码/日志格式标准（见七）；阶段与供应商接口保持统一抽象。
- 验收：全仓 `flake8` 0 error；前后端代码风格统一。

### 5.3 门禁化（有红线、可阻断）
- 动作：按 director 特性重定义 **G0-G6**（见十），`director.py gates` 一键执行。
- 验收：任一门禁失败阻断发布；G2 一键成片门禁在**发布标签**自动跑真实成片。

### 5.4 透明化（有数据、可观测）
- 动作：每阶段埋点（成功率/耗时/成本/供应商/错误码）→ dashboard 看板；health 巡检；覆盖率 HTML 报告；发布历史。
- 验收：看板回答「全链路成功率、各供应商成本、最近发布」；每日巡检可自动化。

### 5.5 规范化（有约束、可拦截）
- 动作：pre-commit 钩子（lint + 快速测试）；git 提交规范（type(scope): subject）；临时文件规范（见 7.4）；文档规范（见八）。
- 验收：违规提交被自动拦截；仓库无新增临时文件。

### 5.6 自动化（有流水线、可回归）
- 动作：CI 增加 lint + 覆盖率门禁；**G2 一键成片回归仅在发布标签/手动触发**（前置 ComfyUI+provider 存活，避免每次 push 因基础设施失败误报）；批量 N 主题→N 成片自动验证；定时健康巡检（Windows 计划任务）。
- 验收：每次 push 全自动跑「lint + 单测 + 冒烟（G0/G1/G4）」；G2 在发布标签触发。

### 5.7 流程化（有文档、可复制）
- 动作：补 3 份 SOP（开发流程 / 测试门禁流程 / 发布流程），与现有操作手册串成完整链路。
- 验收：新人照 SOP 从拉代码到一键发布全程可走通。

## 七、命名与存放规范

### 7.1 目录命名

- 测试：`test_<module>.py` 置于 `tests/`；禁止非测试脚本入 tests/。

- 目录/产物一律 `v<major>.<minor>.<patch>`；禁止 `video_v3`、`real_video_gen_v2` 无规则命名。

### 7.4 临时文件规范
- 一次性脚本 → `scripts/debug/`；调试日志 → `logs/`；禁止在 backend/ 根级产生 `_*.txt/_*.py`。
- 新增代码产生临时文件必须进 .gitignore。

### 7.5 运行时数据
- **目标：全部路径收敛到 `services/paths.py`**；物理位置保持 backend/{data,output,assets,logs}（已被 .gitignore 忽略），可选迁移 runtime/。
- **扫描规范**：任何路径盘点 / grep / 覆盖率统计必须显式排除 `backend/.venv-test/`（已在 .gitignore），避免污染结果。

### 11.1 建议删除清单（纯垃圾）

### 11.3 回滚策略
1. 治理前 commit 全量改动并打标签 `v0.9-baseline`。
2. 每阶段结束打阶段标签 `v0.9-p0` / `v0.9-p1`。

### 11.4 双份 data 数据处置流程（P0 前置）
```
1. 对比根 data/ 与 backend/data/ 各子目录的最近修改时间与文件数
2. 确认当前生效路径（start_backend.bat 从 backend 启动 → backend/data 生效；根 data/ 为历史残留）
3. 两份先各自整体备份到 docs/99_归档/data_<日期>/
4. **并集合并（union-merge）而非 pick-one**：两目录子域不同（根 data/ 独有 canvas/storyboard_intermediates；backend/data/ 独有 generated/gen_task_state），将双方全部子域合并进生效份，避免静默丢弃根目录独有数据
5. 合并完成后，归档另一份（不删除，仅移出）
6. 在 paths.py 收敛时显式声明"运行时数据根目录"，杜绝再次分裂
```
