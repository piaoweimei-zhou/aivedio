## 二、门禁体系（G0-G6）操作

```
python backend/scripts/gates.py          # 默认跑 G0/G1/G3/G4/G6（G2/G5 SKIP）
python backend/scripts/gates.py --g2     # 额外跑 G2 一键成片端到端（需 ComfyUI+provider）
python backend/scripts/gates.py --release # 发布模式（含 G2/G5）
```

## 三、目录约定（含 P3 归档约定）

### 3.1 运行时目录（均已 .gitignore，不入库）

```
backend/
├── data/      # 运行时数据：batches/canvas/generated/task_state/storyboard_intermediates/uploads...
├── output/    # 生成产物：output/(最终) temp/(临时) + 历史归档
├── assets/    # 运行时资产 asset_registry.json
├── logs/      # 应用日志
└── workflows/ # 工作流模板（后端路径收敛到 paths.py）
```

### 3.2 归档约定（P3 治理确立）

- **历史中间产物 / 调试脚本 / 旧报告** → 统一移入 `backend/output/_archive_<日期>/`、`backend/data/_archive_<日期>/`
- 规则：**移动优先、可逆、非删除**；目录名带 `_archive_<YYYYMMDD>` 前缀
- 已在 `.gitignore` 显式声明：`backend/output/_archive_*/`、`backend/data/_archive_*/`
- 归档可随时整目录删除释放空间（不属于当前系统运行的产物）
- 清理历史产物前**先确认时间戳**：保留当前日期（系统在用）目录，仅归档更早的

### 3.3 代码目录命名
- 目录/文件：小写英文 + 下划线（`snake_case.py`）；前端组件 `PascalCase.tsx`
- 测试：`test_<module>.py` 置于 `tests/`；禁止非测试脚本入 tests/
- 一次性调试脚本 → `scripts/debug/`；禁止 backend/ 根级产生 `_*.txt/_*.py`
- 产物目录版本：`v<major>.<minor>.<patch>`，禁止 `video_v3`、`real_video_gen_v2` 式命名

## 四、常用命令速查（venv：`backend/.venv-test`）

```bash
# 代码规范（工作目录 backend/）
python -m flake8 api services core main.py tools scripts tests --max-line-length=100 --exclude=.venv-test
python -m black api services core main.py tools scripts tests --exclude="\.venv-test|__pycache__"

# 测试
python -m pytest tests -q --disable-warnings          # 全量（~210 用例全绿）

# 覆盖率
python -m coverage run -m pytest tests -q --disable-warnings
python -m coverage report --sort=cover                 # 查看排序报表

# 门禁
python backend/scripts/gates.py                        # 从仓库根或 backend 均可
```

> **PowerShell 注意**：复杂 Python 替换/中文内联 `-c` 易被引号破坏，一律写临时 `.py` 脚本执行，用完删除。

## 五、全链路测试方法与已知坑

### 5.1 G2 真实回归（一键成片）

正确驱动方式（`g2_regression.py --full` 的两个调用 bug 已在 af8d265 修复，可直接用官方入口）：

```bash
python backend/tools/g2_regression.py --full --runs 1 --host http://127.0.0.1:8000
```

前置：后端 `start_backend.bat` 运行（8000）+ ComfyUI（8188）+ `.env` 含 provider key。
报告落盘：`backend/data/oneclick_baseline_<时间>.json`。

> **实测结论（2026-08-25 batch_ba6365e5dfb1）：** 全链路 7/7 步骤成功（elapsed≈55 分钟），成片 `backend/data/generated/baseline/export/baseline_export_007_bc7b0a.mp4`（27MB）。**"脚本超时" ≠ "DAG 失败"**：脚本 `timeout_per_batch_s` 默认 1200s 会在长视频渲染期间提前放弃并落盘阶段性报告，但**后端 batch_task_service 的 DAG 会继续执行至完成**。判定最终结果以**后端日志**为准（`logs/app.log` 中 `[DagExecutor] 执行完成 | success=… | completed=N/total` 或 `[BatchTask-DAG] 批量任务完成`），而非脚本报告。

### 5.2 已知坑（务必避免）

| # | 坑 | 规避 |
|---|----|------|
| 1 | ~~`g2_regression.py:full()` 调 `main_async()` 缺 `args` 参数 → TypeError~~ **已修复（af8d265）** | 直接用 `python tools/g2_regression.py --full`；实现：`parse_args()+main_async(args)` |
| 2 | ~~`g2_regression._check_preconditions` 检查 key 名交集误报缺 key~~ **已修复（af8d265）** | 已改为 `load_dotenv(backend/.env)` + 存在任意 KEY/TOKEN 变量即通过；直接用官方 `--full` 即可 |
| 3 | `logs/app.log` 被外部进程持有 → Windows 日志轮转 `PermissionError`（WinError 32） | 属环境噪音，非代码问题；确认无残留 uvicorn/main 进程 |
| 4 | flake8 清理脚本 v1 "F401 整行置空"会破坏多行 import 块、误删 `from typing import ...` 整行 → F821 暴增 | F401 必须 AST 级删名字；多行块 noqa 放块首行 |
| 5 | 多行 import 块的 `# noqa: F401` 必须放**块开始行**才生效 | 放块内单行无效 |
| 6 | 全链路回归单批默认 timeout 1200s，长视频生成易"超时" | 大 timeout（如 3600）或换 provider；**注意脚本超时仅放弃等待，后端 DAG 会继续执行完**，最终判定查后端日志（`[DagExecutor] 执行完成 \| success=`），2026-08-25 实测 7/7 成功 |
| 7 | 真实回归耗时数分钟，ComfyUI 生成时 VRAM 可能 >90% | 避免并发跑其他重活 |
