# 前端组件与类型规范（frontend-director）

> 版本：v1.0（2026-08-27）
> 适用范围：`frontend-director/src/` 全部 TypeScript / TSX 代码
> 治理关联：六化-标准化；门禁：`npm run lint -- --max-warnings 0`（T2 已达标 0 error / 0 warning）
> 本文档是对仓库**既有约定**的沉淀（基于真实代码归纳），不是新引入的外部规范 —— 新代码遵循本文档即与现状一致，不制造额外大 diff。

---

## 1. 目录分层约定

`src/` 采用六层职责分离 + 根入口，共 7 类位置：

| 位置 | 职责 | 放什么 | 现状 |
|---|---|---|---|
| `src/main.tsx` / `App.tsx` / `vite-env.d.ts` | 应用入口 | 挂载、路由骨架、全局类型声明 | 仅 3 个根文件 |
| `src/components/` | 通用/领域组件 | 可复用的 UI 组件（非页面级） | CanvasPanel / Sidebar / Timeline / QcReportCard 等 8 个 |
| `src/pages/` | 页面级容器 | 路由对应的一整页，命名 `XxxPage.tsx` | 16 个页面 |
| `src/services/` | 数据访问层 | axios 实例 + `xxxApi` 对象；WebSocket 封装 | directorApi / canvasRealtime |
| `src/stores/` | 全局状态 | zustand store（`useXxxStore`） | canvasStore / directorStore |
| `src/contexts/` | React Context | 跨页面共享的非全局状态 | ProjectContext |
| `src/utils/` | 纯工具函数 | 无 UI、无状态依赖的辅助函数 | download 等 |

**分层铁律**：
- 页面组件**不直接** `fetch`/`axios`，必须经 `services/` 的 `xxxApi` 访问后端。
- 页面组件**不直接**操作 `useState` 提升到全局的状态，必须经 `stores/` 的 action。
- 组件**不 import** `stores/` 之外的模块副作用（样式/常量除外）。

## 2. 文件与命名规范

| 对象 | 命名 | 示例 |
|---|---|---|
| 组件文件 | PascalCase + `.tsx` | `QcReportCard.tsx` |
| 页面文件 | PascalCase + `Page` 后缀 | `StoryboardPage.tsx` |
| 服务/store/工具文件 | camelCase + `.ts` | `directorApi.ts`、`download.ts` |
| React Context 文件 | PascalCase + `Context` | `ProjectContext.tsx` |
| 接口 / 类型 / 类型别名 | PascalCase | `QcDimension`、`DirectorState` |
| 组件 / 函数 / 变量 | camelCase | `loadAssets`、`batchProgress` |
| 常量 | UPPER_SNAKE_CASE（组件文件内局部常量亦可 PascalCase 约定俗成） | `RADAR_SIZE`、`CENTER` |
| zustand store 导出 | `useXxxStore` | `useDirectorStore` |

**导出约定**：组件、接口、类型一律**具名导出**（`export function` / `export interface`），不用 default 导出 —— 便于引用一致性检查。

## 3. 组件规范

1. **函数组件 + hooks**：全部使用函数组件（`useState` / `useEffect` / `useMemo`），不使用 class 组件。
2. **props 必须显式类型**：props 以**导出的 `interface`** 声明（便于复用与跨文件引用），示例见 `QcReportCard.tsx` 的 `QcReport`。
3. **无状态子组件**：文件内的渲染子逻辑可拆为独立普通函数组件（如 `RadarChart({ dims })`），props 同样显式类型。
4. **组件外提常量**：与渲染无关的常量（尺寸、颜色、文案映射）放在组件函数外部，避免每次渲染重建。
5. **样式**：以 antd 组件 + inline style / style 对象为主；不引入 CSS Modules（当前仓库无此约定）。
6. **副作用**：数据加载在 `useEffect` 内调用 `services/` API；卸载/取消等按既有模式处理。

## 4. 类型规范

1. **后端透传字段保持后端命名（snake_case）**：前端直接消费后端 JSON 的接口（如 QC 报告、资产），字段名与后端一致（`total_score`、`dimensions_list`），以对齐 `docs/01_规划/traffic_contract.openapi.yaml` 契约 —— **不要**在后端字段上做 camelCase 重命名，避免契约漂移。
2. **避免 `any`**：当前 eslint 关闭 `no-explicit-any`（存量代码较多 `any`），但**新代码应尽量具体化**——优先用具体 `interface`、`Record<string, unknown>`、联合类型；仅在无法穷举的外部数据边界允许 `any` 并加注释说明。未来可评估开启严格模式作为 ratchet。
3. **复用型类型必须导出**：被多个文件引用的类型（组件 props、store state、API 响应）在定义处具名导出，不重复内联。
4. **响应数据类型**：API 层方法应标注返回类型（`Promise<Asset>`、`Promise<QcReport>`），不返回裸 `any`。

## 5. API 层规范（services/）

1. **统一 axios 实例**：`axios.create({ baseURL: '/api/director', timeout: 30000 })` 作为唯一入口（见 `directorApi.ts`），**不要**在各页面各自 `axios.get`。
2. **按域分组对象**：`export const xxxApi = { list, get, create, update, delete, ... }`，方法名与 REST 语义一致。
3. **方法返回数据**：`api.get(url).then(r => r.data)`，对外暴露的是后端 JSON 数据而非 axios response。
4. **特殊超时**：上传/长耗时接口单独覆盖 timeout（如 `upload` 用 120000）。
5. **错误处理**：由调用方（页面/store）统一 try/catch + antd `message` 提示；API 层不吞错误。

## 6. Store 规范（zustand）

1. **集中定义 State 接口**：`interface DirectorState { 数据 + loading + actions }`，`create<DirectorState>((set, get) => ({...}))`。
2. **单向数据流**：WebSocket 事件 → store action（`updateBatchProgress`）→ 组件订阅 —— 组件**不直接**处理 WS 事件写状态（见 `directorStore.ts` 批量任务注释）。
3. **selectors 粒度**：组件按需订阅字段，避免整 store 重渲染。
4. **异步 action 返回 Promise**：让调用方可以 `await` 后做后续处理。

## 7. 工具函数规范（utils/）

1. **纯函数**：无副作用、无 DOM 依赖（DOM 操作在函数内部按需封装）。
2. **JSDoc 注释**：每个导出函数带 `/** ... @param ... @returns ... */`（见 `download.ts`）。
3. **UI 反馈**：需要提示时用 antd `message`，不在 utils 内直接 `console` 刷屏。

## 8. 风格一致性与门禁

| 项 | 当前状态 | 约定 |
|---|---|---|
| 分号 | eslint **未启用** `semi` 规则（存量代码有分号/无分号混用） | 不做强制；**新文件建议无分号**（services/stores/utils 主流风格）；改动旧文件保持该文件既有风格，避免无谓大 diff |
| `any` | `no-explicit-any: off`（存量兼容） | 新代码尽量具体化（见 §4.2），存量 `any` 不强制清理 |
| react-hooks v7 新规则 | `set-state-in-effect` / `immutability` 已 `off`（2026-08-27 全量审计：全部为"异步加载后 setState / 渲染期引用加载函数"的正常模式，非 bug） | 新代码若出现**真**的 effect 中无限循环，靠 `exhaustive-deps`（保留）+ code review 拦截 |
| 门禁 | `npm run lint -- --max-warnings 0` | 0 error + 0 warning，CI 与 pre-commit 双端强制 |

- [ ] 后端透传字段保持 snake_case（对齐 OpenAPI 契约）
- [ ] 无新增 `any`（必要时加注释）
- [ ] `npm run lint` 0 error / 0 warning
- [ ] 命名符合 §2 表格
