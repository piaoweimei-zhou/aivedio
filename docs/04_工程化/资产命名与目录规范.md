# 资产命名与目录规范

> 全链路生成资产（概念图 / 分镜 / 视频 / 音频 / 导出成片）统一存储与命名的约定文档。
> 配套实现：`backend/services/asset_organizer.py`；存量迁移脚本：`backend/tools/migrate_assets.py`。

---

## 1. 背景与目标

历史版本把所有生成资产平铺写入 `backend/data/generated/` 根目录，文件名是 ComfyUI 的流水号（`ComfyUI_00001_.png`）或带缺陷的前缀（`nknown_storyboard_*`），存在三个问题：

1. **难找**：几百个文件堆在一个目录，无法按项目 / 阶段 / 内容快速定位。
2. **难认**：文件名不含语义，看不出是哪个项目、哪个阶段、什么内容。
3. **易冲突**：ComfyUI 流水号跨批次复用，同名文件可能互相覆盖。

本规范的目标：

- **按项目 + 阶段分层目录**，一眼看清资产归属。
- **语义化文件名**，含项目、阶段、内容、序号、短哈希，可检索、可排序、防冲突。
- **全链路自动生效**，新生成资产无需人工整理。

---

## 2. 目录结构规范

所有生成资产统一存放在：

```
backend/data/generated/{project_id}/{stage_id}/
```

| 层级 | 取值 | 说明 |
|------|------|------|
| `project_id` | 项目 ID（清洗后） | 空值 / `unknown` 兜底为 `global` |
| `stage_id` | 阶段 ID | `concept` / `storyboard` / `video` / `export` / `tts` / `pano` / `refine` 等 |

示例：

```
data/generated/
├── global/                    # 无项目归属的资产（存量迁移 / 单次生成）
│   ├── concept/               # 概念图（含 prop / multi_person 内容分类）
│   ├── storyboard/            # 分镜帧
│   ├── video/                 # 视频成片
│   ├── tts/                   # 语音 / 音频
│   ├── pano/                  # 360 全景
│   └── refine/                # 精修 / 超分
└── my_project/                # 按项目隔离（新链路自动生成）
    ├── concept/
    ├── storyboard/
    └── video/
```

> 目录名与文件名中的非法字符统一替换为 `_`，关键词长度上限 12 字符。

## 3. 文件名命名规范

### 3.1 通用格式

```
{project_id}_{stage_id}[_{content_keyword}]_{seq:03d}_{hash6}.{ext}
```

| 段 | 示例 | 说明 |
|----|------|------|
| `project_id` | `my_project` | 项目标识，空 / `unknown` 用 `global` |
| `stage_id` | `storyboard` | 生产阶段 |
| `content_keyword` | `character` / `scene` / `prop` | 内容关键词（可选，无则省略） |
| `seq` | `001` | 同目录内递增序号（3 位补零） |
| `hash6` | `29dcd5` | 源文件名 6 位短哈希，防同名冲突 |
| `ext` | `.png` / `.mp4` / `.flac` | 扩展名（小写） |

### 3.2 示例

```
# 项目 my_project 的分镜第 3 帧
my_project_storyboard_003_e6b584.png

# 全局（无项目）概念图，内容为道具
global_concept_prop_001_bc3088.png

# 全局视频成片
global_video_002_83fac0.mp4
```

### 3.3 规则要点

- **序号按目录 + 内容关键词独立计数**：`concept/character` 与 `concept/scene` 各自从 001 开始。
- **短哈希保证唯一**：即使源文件名相同（如 ComfyUI 流水号复用），目标文件名也不会冲突。
- **扩展名统一小写**，便于前端媒体类型识别。
- **禁止路径遍历**：文件名仅取 `basename`，目录段同样校验，拒绝 `..` 与绝对路径。

## 4. 实现机制

### 4.1 运行时自动整理

所有阶段插件的资产注册统一走 `StagePlugin._register_asset` / `_register_asset_direct`，二者在注册前调用 `_organize_urls`：

1. 从 `ContextVar` 读取当前 `project_id`（并发安全，避免单例竞态）。
2. 调用 `organize_asset_files` 把本地文件移动到 `data/generated/{project}/{stage}/` 并重命名。
3. 用**移动而非复制**（`_persist_output_files` 已在根目录留有副本，避免重复堆积）。
4. 远程 URL（云端 provider 产物）无法本地定位，原样保留。

覆盖阶段：`concept` / `angle` / `pano` / `storyboard` / `refine` / `video` / `edit` / `export` / `tts` / `subtitle` / `hook_overlay` 等全部内置阶段。

### 4.2 文件访问

- 新 URL 格式：`/api/comfyui/image?filename={name}&subfolder={project}/{stage}`
- 兼容旧 URL：`/api/comfyui/image?filename={name}` 不带 `subfolder` 时，端点会**递归查找**持久化目录，存量引用迁移后仍可访问。

### 4.3 已知边界

以下旁路流程暂未接入整理器（属边缘场景，主链路已全覆盖）：

- 画布资产库同步（`infinite_canvas_api.py` 的 `asset_svc.create`）
- MSR 多角色视频下载注册（`canvas_api.py`）

## 5. 存量资产迁移

历史平铺文件可用迁移脚本整理：

```bash
# 预览（默认，不移动文件）
python backend/tools/migrate_assets.py --dry-run

# 实际执行（默认移动）
python backend/tools/migrate_assets.py --apply

# 复制而非移动（保留源文件）
python backend/tools/migrate_assets.py --apply --copy

# 迁移后同步更新资产注册表 URL（推荐，避免旧引用失效）
python backend/tools/migrate_assets.py --apply --update-registry

# 指定目录
python backend/tools/migrate_assets.py --generated-dir <path>
```

迁移按文件名前缀推断阶段，归入 `global/{stage}/`：

| 前缀 | 阶段 | 内容 |
|------|------|------|
| `nknown_storyboard_` | storyboard | （depth / lineart / pose 单独分类） |
| `nknown_refine_` | refine | - |
| `prop_` | concept | prop |
| `multi_person_` | concept | multi_person |
| `panorama_final_` | pano | - |
| `minimax_h3_` / `mmh3_` | video | - |
| `ComfyUI_*.png` | concept | - |
| `ComfyUI_*.flac` | tts | - |
| `MSR_verify_` | test | - |

> 存量文件无项目归属信息，统一归入 `global/`。新生成资产会按真实项目 ID 自动分层。

### 5.1 注册表 URL 修复

迁移会把文件**移动 + 重命名**为语义名，资产注册表（`backend/assets/asset_registry.json`）中指向旧文件名的 URL 会失效。用修复脚本通过短哈希反推定位新文件并更新 URL：

```bash
# 预览
python backend/tools/repair_asset_registry.py --dry-run

# 实际写回注册表
python backend/tools/repair_asset_registry.py --apply
```

> 迁移时加 `--update-registry` 可自动执行此步骤。无法修复的 URL 属于文件早已丢失的历史孤儿引用（如测试残留、未持久化的画布视频），与迁移无关。

## 6. 常见问题

**Q：为什么文件名里还有 `global` 而不是项目名？**
A：该资产生成时未携带项目上下文（如存量迁移、单次生成）。新链路只要传入 `project_id` 就会自动用真实项目名。

**Q：`unknown` 会出现在文件名里吗？**
A：不会。`sanitize_keyword` 与 `_project_prefix` 都把空值 / `unknown` 兜底为 `global`，已修复历史 `nknown_*` 缺陷。

**Q：移动文件会不会导致旧引用失效？**
A：不会。`/api/comfyui/image` 端点对不带 `subfolder` 的旧 URL 做递归查找，迁移后仍能访问。

**Q：同名文件会不会互相覆盖？**
A：不会。目标文件名带 6 位短哈希 + 递增序号，天然防冲突。
