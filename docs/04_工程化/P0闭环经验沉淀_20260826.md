P0 从"裸 5s 视频"升级为"**平台规格 + 真实配音 + 字幕 + 钩子 + 导出**"的完整成片，且 contract 状态从"黑盒"变成"分步+ComfyUI 实时进度可见"。本档记录 4 个根因级问题与修复，以及 1 个未闭环断点。

## 1. 【严重】单段（1 镜）配音丢失 —— TTS 根本没在 ComfyUI 执行

### 现象
用户播放 5s 成片听不到人声旁白；ComfyUI 日志无任何 Qwen3-TTS 调用记录。5 步流程（concept→video→subtitle→hook→export）跑完，video 只有 H3 模型自带的音效，无 TTS 人声。

### 根因（两层）
1. `video_stage.py` 的 TTS 混音逻辑只在**逐镜路径** `_generate_h3_segmented()` 里生效：
   ```python
   if (provider_id == "minimax_h3" and (segment_prompts or force_segmented)
       and len(tts_texts or segment_prompts) > 1):   # ← 单段时为 False
   ```
   单段（1 段 5s）时 `len(...) > 1` 为 False → 走 else 分支直接 `generate_video(tts_texts=...)`。
2. 但 minimax_h3 provider 的普通 `generate_video` **不注入人声**（设计上"H3 人声由逐镜独立 TTS 提供"，见注释）。所以台词被静默丢弃，成片无旁白。

### 修复
`video_stage.py` 条件追加"单段但有台词也走逐镜路径"：
```python
or bool(tts_texts and any(t.strip() for t in tts_texts))
```
逐镜路径 `_gen_tts_segment()` → `_mix_tts_into_segment()` 对每镜 seg_text 非空必执行 TTS 混音。

### 验证（铁证）
ComfyUI 日志 005 任务出现 **`Loading Qwen3-TTS Model ... Prompt executed in 11.56 seconds`**（004 无此记录）。音频 volumedetect 确认非静音。

### 经验
- **"功能已实现"≠"该路径生效"**。多分支代码要特别检查**单元素边界**（1 段 vs N 段）是否走了预期的分支。
- 验证配音不能只看音轨是否存在（H3 自带音效也有音轨），要**确认 TTS 调用记录**（日志关键词）或实际听。

## 2. 【中】封面标题重复渲染 —— packaging 模板语义误用

### 现象
封面大字 "3 秒解决 **3秒解决短视频去水印…**，亲测可用"（重复 + 截断）。

### 根因
`generate_packaging(topic_title, ...)` 的 title 参数语义是**主题词（topic）**，模板 `"3 秒解决 {topic}，亲测可用"` 会拼出完整标题。P0 调用时误传了**完整标题**当 topic → 模板再次包装 → 重复。

### 修复（调用语义，非代码）
调用 `build_publish_package` 时 `title` 传主题词（如"短视频去水印"），由模板生成完整标题。修复后封面单行 "3 秒解决 短视频去水印，亲测可用" ✓。

### 经验
- 调用第三方/内部函数前先确认参数语义（topic vs 完整标题），避免"模板套模板"。

## 3. 【中】contract 进度黑盒 —— ComfyUI 生成中状态不可见

### 现象
用户问"ComfyUI 生成了但状态不知道"。contract `GET /produce/{task_id}` 只返回 `status/progress/current_step`，且 done 后 `current_step` 停在上一步，无分步信息、无 ComfyUI 实时状态。

### 修复
1. `TaskDetail` 增加 `steps[]`（step_id/stage_id/status/elapsed_ms，来源 `batch.steps`）与 `comfyui`（在线状态 + 队列进度，用 `ComfyUIClient.get_queue_progress(prompt_id)`）。
2. 踩坑：`batch.steps[i]` 是 **BatchStep 对象** 非 dict，`.get()` 会 500 → 改用属性访问（`st.stage_id` 等）。

### 效果
```
steps: [{concept completed 173s}, {video completed 464s}, {subtitle 1.3s}, {hook 1.1s}, {export 2.5s}]
comfyui: {online:true, in_queue:false}
```

### 经验
- 进度透明化 = **分步状态 + 底层引擎实时状态**，两者缺一都会让用户误判。
- 遍历"看似 dict 的对象"前先确认真实类型（pydantic model vs dict）。

## 4. 【低】contract 平台化 —— 概念图阶段即定比例

### 改动
`PLATFORM_PROFILES` 平台画像驱动三处：
- concept `size`（抖音/快手 1080×1920、小红书 1080×1440、B站 1920×1080）
- video `aspect_ratio + width/height`（720×1280 / 720×960 / 1280×720）
- export `resolution`（1080×1920 / 1080×1440 / 1920×1080）

### 效果
抖音 5s 成片 1080×1920 竖版 ✓（此前硬编码 1024×1024 方图）。

## 5. 【未闭环】热点库断点诊断 —— 有数据但链路空转

### 现状核查
- `topics` 集合 **81 条真实热点**（含外部来源，"台风来了如何应对"等），有数据。
- `hotspots` 集合 **0 条**（原始热点缓存空，但 topics 已同步过）。
- `signals` 集合 **0 条** → `GET /signals/suggest-topics` 返回空 suggestions。
- **P0 手动闭环完全没走"热点选题 → 生成脚本 → contract"链路**，narration 是硬编码的。

### 断点
热点 → 内容 的自动化链路断了：选题推荐依赖 `signals`（用户行为信号）为空；且生产侧 contract 未接 topics 数据。

### 待办（建议下一步）
1. `suggest-topics` 增加**无 signals 时的兜底**：从 topics 库按 dimension/monetizer 直接抽取（而非仅信号匹配）。
2. 打通"热点选题 → 生成 narration/script → POST /contract/produce"的自动编排（TrafficOS 侧写 orchestrator 或人工半自动先跑通）。
3. **内容安全**：topics 里存在政治敏感话题（如"这项任务总书记强调久久为功"），自动选题必须加过滤黑名单，避免生产违规内容。

## 7. 【致命·第三层】混音成功但成片仍无声音 —— result.images 未同步

### 现象
005/006 修复"单段走逐镜 TTS"后，ComfyUI 日志确认 Qwen3-TTS 执行、混音产物 seg_tts_*.mp4 生成且音轨响亮（mean -25.9dB），但**成片 export 仍静音**（mean -68.8dB，≈ H3 原片静音轨）。

### 铁证（ffmpeg volumedetect 三段对比）
| 音轨 | mean_volume | 结论 |
|---|---|---|
| H3 原片 video_scene_004 | -68.7 dB | 静音 |
| 混音 seg_tts_651c4f10 | **-25.9 dB** | 含人声 ✓ |
| export 成片 | -68.8 dB | 静音 ✗（丢了混音） |

### 根因（两层叠加）
1. `_register_asset` 注册 asset 用 **`result.images or [result.image_url]`**（不是 `video_url`）。
2. 逐镜路径 `_generate_h3_segmented` 单段分支只改了 `r.video_url / r.image_url`，**`r.images` 仍是 H3 原片**（ProviderResult 构造时固化为 `images=[h3原片]`）→ asset 注册到 H3 静音原片 → subtitle/hook/export 全部用无声源。

多段正常的原因：多段拼接走 FakeResult，`images=[merged_url]`（含人声）。

### 修复（1 行）
混音成功后同步 `r.images = [mixed_url]`。提交 f7cf17b。

### 验证
007 重跑：export 成片 mean **-22.1dB**（含真实人声）✓；新增回归测试 test_single_seg_tts_updates_images_to_mixed_url（断言 result.images==[mixed_url]）✓；全量 284 passed。

### 经验
- **"有音轨"≠"有人声"**：验证配音必须对比 H3 原片音轨 vs 混音产物 vs 最终成片的音量级，逐段定位丢失环节。
- **注册/传递用哪个字段就测哪个字段**：多字段对象（video_url/image_url/images）在链路中被不同环节消费，改一个字段必须同步所有消费方字段。
