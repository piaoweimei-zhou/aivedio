# 系统作为「流量视频生产工具」的差距判断
一句话结论 ：管线的"脚手架"够用（架构、异步队列、供应商抽象都是工业级），但差 短视频的最后一公里 —— 字幕、卡点剪辑、网感风格、钩子模板这 4 块。 建议直接拿一个案例测，测完再决定优化优先级 ，不要先优化。

## 一、真实需求 vs 现有能力（环节级差距）

最痛的 3 个缺口 ：① 字幕自动生成 ② 卡点剪辑模板 ③ 网感风格调参。前两个是纯工程（ffmpeg 能干），第三个是工作流调参。都不需要动核心架构。

## 二、优化路线图（轻量增量，不动架构）
### Phase 1（3-5 天）：补字幕 + 钩子 —— 最高 ROI
- 新增 subtitle_stage ：用 whisper 或复用 TTS 时间戳 → 生成 ASS 字幕（竖版大字、关键词描边高亮）→ ffmpeg 烧录
- 新增 hook_overlay ：结尾 3 秒固定引导框（"评论区扣 1 领工具"模板化），ffmpeg overlay
- 这两块纯 ffmpeg，零模型成本，直接补上短视频最大短板
### Phase 2（5-7 天）：卡点剪辑模板
- 扩展 EditPage ：预设 3-5 个"卡点模板"（BGM 节拍点 + 音效 + 转场），输入 N 个 5 秒片段 → 自动卡点拼成 30 秒
- 实现：ffmpeg filter_complex + 预设时间轴，不引入新模型
### Phase 3（持续）：网感风格调优
- 新建 1 个"网感文生图"工作流：降步数到 15、换 SDXL 基础模型、prompt 往"手机拍摄、室内日光灯、生活感"调，区别于现有"影视级"
- script stage 注入"钩子库 + 反转模板库"做 few-shot，提升脚本网感
判断 ：Phase 1 必做，Phase 2 锦上添花，Phase 3 边测边调。 但都建议先跑一个原始案例测完再优化 ——否则优化方向可能跑偏。

## 三、直接测：一个可立即执行的案例
案例：《设计师改 100 张图》 （小红书/抖音竖版 30 秒）

### 用现有系统的调用步骤（后端启动后可直接跑）
Step 1 — 剧本 （ script stage ）

Step 2 — 生图 （对每个分镜， concept stage ）
 注：现有 最终文生图.json 默认影视级，建议这一步先在 prompt 里强加"手机拍摄、生活感、非电影质感"对抗默认风格。Phase 3 再做专用工作流。
Step 3 — 视频生成 （每个分镜图， video stage ）
 即梦出 5 秒/条，6 个分镜并发提交，靠 GenTaskManager 排队。
Step 4 — 配音 （ Qwen3+TTS+音色设计.json ，对每段配音文案）

Step 5 — 剪辑拼接 （ EditPage / edit stage）

Step 6 — 字幕（手动补，因为系统没有） 用剪映/Arctime 把配音文案做成竖版大字幕烧录进去。结尾加"扣1"引导框。

## 四、测试后该看什么（决定是否优化）
发布 1 条到小红书，48 小时后看 3 个数：

指标 判断标准 不达标说明 完播率 >30% <20% → 剪辑节奏/钩子要优化（Phase 2） 评论扣1数 播放量×1% <0.3% → 钩子话术/引导框要优化（Phase 1） 加微信数 评论数的 30% <10% → 引流路径要优化

只有完播率达标但加微信率低 → 做 Phase 1（钩子/字幕）。 完播率不达标 → 先做 Phase 2（卡点剪辑），这是最大的内容质量问题。 画面被说"像AI" → 做 Phase 3（网感风格）。
