## 一、核心原则

### 原则 1：资产网络，而非线性管线

传统管线是 A→B→C→D 固定顺序，但真实的短剧创作是**网状结构**：

```
角色概念图 ───→ 三视图 ───→ 分镜换装 ───→ 视频生成
场景图 ───────→ 360全景 ──→ 分镜背景 ──→ 
物体图 ───────→ 线稿提取 → 深度图 ───→ 多图融合
任意资产 ─────→ 精修/超分 → 回资产库（非破坏性迭代）
```

因此，核心架构是 **AssetService + StageRegistry + ProviderService** 三层解耦，而非管线执行器。

### 原则 2：开源闭源结合

| 层级 | 技术 | 来源 |
|------|------|------|
| 开源本地推理 | ComfyUI + Qwen/Flux | 已有部署 |
| 开源画布 | Infinite-Canvas canvas.html | 网盘会员最新版 |
| 开源时间线 | ltx-director-timeline.js | 网盘会员最新版 |
| 闭源图片 | OpenAI / Gemini / ModelScope API | Infinite-Canvas |
| 闭源视频 | 即梦 CLI / RunningHub / 火山引擎 API | Infinite-Canvas |
| 闭源 LLM（预留） | DeepSeek / Qwen API | Phase 5+ |

所有供应商通过 `ProviderService` 统一抽象，前端无感切换。

### 原则 3：不重复造轮子

| 已有模块 | 处理方式 | 原因 |
|---------|---------|------|
| V6.0 分镜模板系统 | **直接复用** | 已修复 16 个问题，稳定可用 |
| Infinite-Canvas 供应商函数 | **抽取包装** | 做隔离层，不改逻辑 |
| Infinite-Canvas 资产库 CRUD | **直接复用** | 含 asset_library.json + WS 广播 |
| 即梦 CLI 安装/登录脚本 | **直接复用** | tools/ 目录已有 |
| canvas.html (33KB) / angle.html (58KB) | **iframe 嵌入** | 不 React 重写 |
| ltx-director-timeline.js (146KB) | **Web Component 包装** | 嵌入 React |

### 2.2 Stage 插件系统

每个生产阶段是一个独立插件，新增能力 = 注册一个新 Stage + 配一个新 Provider，不修改核心架构。

```python
@dataclass
class StageDef:
    """阶段定义"""
    stage_id: str                     # 唯一标识
    name: str                         # 显示名
    input_types: List[str]            # 输入资产类型
    output_type: str                  # 输出资产类型
    default_provider: str             # 默认供应商
    supported_providers: List[str]    # 支持供应商列表

class StagePlugin(ABC):
    """阶段插件基类"""
    @abstractmethod
    async def execute(
        self, input_assets: List[AssetRef],
        provider: ProviderPlugin,
        params: Dict
    ) -> AssetProduceResult: ...

class ProviderPlugin(ABC):
    """供应商插件基类"""
    @abstractmethod
    async def generate(
        self, inputs: Dict[str, Any],
        params: Dict
    ) -> ProviderResult: ...
```

### 2.3 资产生产-消费数据流

```
用户：选择"角色概念图" → "生成三视图"

  1. AssetService.consume(角色图)
  2. StageRegistry.resolve("concept→multi_view") → AngleStage
  3. AngleStage.execute() → ProviderService.generate("modelscope")
  4. ModelScope API 生成三视图
  5. AssetService.produce({type:"multi_view", urls:[正面,侧面,背面]})
  6. WebSocket 广播资产库更新


用户：选择"角色图+场景图" → "分镜换装"

  1. AssetService.consume_multi([角色, 场景])
  2. StageRegistry.resolve("character+scene→storyboard") → StoryboardStage
  3. StoryboardStage.execute() → 调 pipeline_api (复用 V6.0)
  4. AssetService.produce({type:"storyboard", urls:分镜帧[]})


用户：选择分镜帧 → "生成视频"

  1. AssetService.consume(分镜帧)
  2. StageRegistry.resolve("storyboard→video") → VideoStage
  3. VideoStage.execute() → ProviderService.generate("jimeng")
  4. 即梦 CLI 异步提交 → 轮询完成
  5. AssetService.produce({type:"video", urls:[mp4]})
```

## 五、与 AI-IDE-v2 的边界

| 维度 | AI-IDE-v2 (frontend-react/) | 导演工作台 (frontend-director/) |
|------|---------------------------|-------------------------------|
| 核心定位 | 通用 AI 代码助手 + 图片生成 | 短剧/视频创作者的全栈工具 |
| 用户群 | 开发者 | 编剧、导演、视频创作者 |
| 界面风格 | 代码编辑器风格 | 视觉化画布 + 时间线 |
| 核心功能 | 代码生成/微调/MLOps/图片 | 剧本→分镜→视频→剪辑→成片 |
| 共用服务 | pipeline_executor, comfyui_service | AssetService, ProviderService |
| 数据独立 | 各自独立的 Zustand store | 各自独立的 Zustand store |
| 部署 | 统一后端，前端分端口开发 | 统一后端，前端分端口开发 |
