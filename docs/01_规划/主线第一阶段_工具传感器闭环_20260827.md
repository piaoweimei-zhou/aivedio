# 主线第一阶段：工具传感器闭环（真实数据源）v1.0

> 日期：2026-08-27 ｜ 状态：方案已定，开始执行 ｜ 主线定位：内容工厂商业化闭环（M1 常态化）
> 决策记录：本方案是「5 问题 × 主线四要素」战略对齐的落地文档（用户确认"沉淀下来开始执行"）

---

## 0. 一句话定位

**把已存在的去水印工具（`bupvideo/tools/watermark_remover`）升级为 TrafficOS 的真实数据传感器**：批量解析平台真实视频 → 拿真实互动/播放数据 → ①真实热点选题（替代榜单）②自产视频分时段轮询 → ROI 趋势数据。接通后，主线四要素中「选题 × 数据飞轮」基本解锁。

---

## 1. 背景：主线四要素与 5 问题的映射（2026-08-27 战略对齐）

主线 = 内容工厂商业化闭环。四要素：**选题 × 产量 × 数据飞轮 × 平台适配**。

当前 5 个卡点与四要素的覆盖关系（**解决 5 问题 ≠ 全解四要素**）：

| 主线四要素 | 对应解决的卡点 | 覆盖度 | 解锁后状态 | 剩余缺口 |
|---|---|---|---|---|
| **选题** | 卡点4（traffic 热点不靠谱）+ 卡点5（工具真实热点） | ✅ 基本解决 | 真实互动数据排热点，垂直、可量化命中率 | 需数据积累才有命中率统计 |
| **数据飞轮** | 卡点3（飞轮没转）+ 卡点5（工具轮询数据） | ✅ 基本解决 | 真实数据点（B站播放/抖音互动）→ 趋势 → 回灌选题 → 飞轮真转 | 抖音无播放量，ROI 需 proxy 换算 |
| **产量** | 卡点2（19 项跑起来，部分） | ⚠️ 只一半 | 生产侧批量/门禁能力真跑，但单批卡本地 GPU(16GB)+ComfyUI 单实例 | **GPU 承载是硬瓶颈**（规模化分水岭） |
| **平台适配** | 卡点1（抖音权限）+ 数据侧适配 | ⚠️ 只一半 | 数据侧多平台解析/规格已就绪；发布侧仍半自动 | 全自动发布受平台权限限制 |

**决策**：先做 5 问题闭环（纯软件+已有工具，不依赖外部资源），把"大脑和神经系统"（选题+飞轮）接通；GPU 承载与全自动发布作为下一棒，等真实数据验证选题/ROI 价值后再投入。

## 4. 方案：工具传感器闭环

```
┌─────────────────────────────────────────────────────────────┐
│  去水印工具（已存在，多平台解析）                              │
│    ├─ A. 热点采集：批量解析"话题/账号/榜单"视频 → 真实热度排行 │
│    │     → 写 topics（hot_source=auto_tool）→ 选题打分        │
│    └─ B. ROI 轮询：自产视频 URL 定时解析 → 数据点(播放/互动)   │
│          → 趋势曲线 → metrics → ROI 归因 → 周报              │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 A 线：真实热点采集（替代/增强榜单）
- 输入：种子话题/账号/榜单 URL 列表（与百度热点并集）
- 动作：批量解析 → 按"播放量/互动量 × 时效"打分 → 去重
- 输出：`topics`（标记 `hot_source=auto_tool`，含真实数据字段）+ 热度排行
- 价值：垂直领域真实热度，选题命中率可量化

### 4.2 B 线：ROI 数据轮询（飞轮数据源）
- 输入：自产已发布视频的 URL 清单（contract 产物）
- 动作：分时段定时轮询（如每日 2 次）解析 → 追加数据点
- 输出：每视频 `{ts, plays/互动}` 序列 → 增长趋势 → 估算收益 → ROI
- 平台策略：B 站用真实 plays；抖音用互动 proxy（`播放≈likes×K`，K 需经验校准后固化）

### 4.3 与现有系统对接（复用已有）
- `ToolTracker.track_download()`（SDK）→ `/api/traffic/signals/tool-event` → hits 拆解库（P1b 已通）
- `signals.suggest_topics` → 选题建议（B8 已通）
- `analytics` ROI 聚合 + `/reports/weekly`（P1d 已通）
- **新增**：采集器（定时批量解析→上报）与轮询器（自产视频→数据点）

## 5. 落地形态（已定：B 封装服务）

- **A 直连采集**（快）：bupvideo 侧写采集脚本，解析后直连 TrafficOS API 上报。当日可通，适合快速验证。
- **B 封装服务**（工程化）：解析能力封装为 TrafficOS 采集服务（可复用、可调度、可测试）。

**决策（2026-08-27）**：**选定 B**——解析核心迁入 TrafficOS 仓（`trafficos/app/collectors/`），原因：
1. bupvideo 本地门禁（git hook）全仓 pytest 收集卡死于 `test_import_mainwindow.py`（import 主窗口触发 GUI/激活初始化），与主线无关，不值得为提交打补丁；
2. 采集能力归属流量侧（TrafficOS）更内聚，落在有完整门禁（三端 flake8 + conventional commit）的 director/aivedio 仓内，可测试、可持续；
3. 迁入代码收敛为 B 站链路（仅 `requests`+parser_base，无浏览器依赖），A/B 两线均可用；抖音等需 Playwright 的平台后续有需要再迁。

落地位置：`trafficos/app/collectors/`（collector.py + parser_base/ + parsers/ + seeds.txt），测试 `trafficos/tests/test_collector.py`（8 用例）。

## 6. 合规边界（先立好再动手）

- **只做聚合分析/内部选题**，不搬运、不二次分发平台内容
- 采集频率克制（防限流），轮询仅限**自己发布的视频** + 公开数据分析
- 抖音交互走 Playwright 无头（无登录态），遵守平台 robots 与频控
- 数据仅用于 TrafficOS 内部选题与 ROI 归因，不外泄

## 8. 风险与决策

| 风险 | 应对 |
|---|---|
| 平台风控/接口变化 | 解析器已多平台；采集克制；失败降级（榜单兜底） |
| 抖音无播放量 | 互动 proxy 换算，标注"估算值"；优先 B 站验证 ROI |
| 采集被限流 | 频率控制 + 指数退避 + 多平台分摊 |
| 工具解析偶发失败 | 解析器已有重试/错误码体系，采集器需容错统计 |
